# Quality Gates & Performance — Design Spec

Date: 2026-10-03
Status: Draft, awaiting maintainer review
Sub-project 1 of 2 (sub-project 2: AI tooling, specced separately)
Builds on: `2026-06-24-quality-a11y-design.md` (WPCS across all PHP, axe a11y gate). Nothing here changes those gates.

## Goal

Make StrataWP the framework whose own code, and whose generated themes, are held to the strictest performance and quality bar available out of the box. Every generated theme starts with the same gates the monorepo enforces.

## Decisions (agreed with maintainer)

- **Enforcement:** new gates are blocking in CI from day one. Existing violations in the example themes are fixed as part of this work.
- **Scope:** gates apply to the monorepo and to themes generated by `create-stratawp`.
- **Packaging:** each gate lives in the package that already owns that concern. No monolithic quality package.
- **Delivery:** one PR on branch `feat/quality-gates`, with ordered, individually revertable commits. Files are staged by explicit path, never `git add -A` or `git add .`.

## Current state (audited)

Already present and out of scope here: Lighthouse CI (`.lighthouserc.cjs`, `perf.yml`), PHPCS across all PHP, PHPStan on core (`ci.yml`), axe-core front-end a11y on Chromium (`a11y.yml`, `examples/basic-theme/e2e/a11y/`), ESLint, Prettier.

Also present: `@stratawp/testing` already exports a Playwright preset (`playwright` subpath, WP helpers) with five browser projects, and `examples/basic-theme/e2e/block-editor.spec.ts` (editor flow via `wpLogin`) that no CI job collects.

## Scope

### 1. AVIF output (`@stratawp/vite-plugin`, core)

- `images.ts` emits `*.avif` alongside `*.webp` and the original. Config: `images.formats` (default `['avif', 'webp']`); a subset opts out.
- Encoding failure for a file warns and skips that format for that file. The build never fails on it and never leaves a partial file.
- Output is deterministic so cached builds are stable.
- PHP helper in `packages/core/src/Components/ImageSizes.php` emits `<picture>` sources ordered AVIF, WebP, original. A `<source>` is emitted only when the sibling file exists on disk.

### 2. `@stratawp/stylelint-config` (new package)

- Pure-data preset: nesting depth limit, specificity cap, custom-property naming convention (kebab-case, WordPress `--` segments allowed). Unknown-reference checking is out of scope: `theme.json` generates `--wp--preset--*` tokens that Stylelint cannot be seeded with, so such a rule would flag all of them. Depth 3 means three nesting levels inside the root rule: four selectors deep passes, five fails; pseudo-classes and at-rules do not count. A scoped exception raises the specificity cap to `0,5,2` for files matching `**/*woocommerce*.{css,scss}`, because overrides of WooCommerce core selectors must match their specificity to win; the global cap stays `0,3,1`.
- Thresholds are overridable per theme and each rule documents its rationale.
- Violation output names the rule and location; the specificity rule also names the offending selector.
- Initial thresholds (depth 3, specificity cap) are proposals. They are confirmed by running the preset against the examples before being committed; if cleanup is large, thresholds are revisited with the maintainer first.
- Example themes' CSS/SCSS is fixed to pass.

### 3. Cross-browser smoke tests (`@stratawp/testing`, `examples/basic-theme`)

- The axe a11y gate stays Chromium-only (axe results are engine-independent; unchanged).
- Add a separate smoke Playwright config for `basic-theme` that runs Chromium, Firefox, and WebKit. CI runs the full matrix; local runs default to Chromium.
- Reconcile with the existing `@stratawp/testing` preset: the preset's project list is reduced to the three desktop engines the smoke config uses, or the smoke config extends the preset. The implementation plan picks whichever leaves one source of truth.
- `baseURL` from an env var, defaulting to the wp-env URL (`:8888`). Global setup fails fast with one clear message if the site is unreachable.
- Retries on in CI and off locally. Traces kept on failure. Browser binaries are cached where Playwright's guidance allows; otherwise the extra install time is accepted and measured.
- New front-end smoke tests: navigation (including mobile menu) and pattern rendering. `block-editor.spec.ts` stays out of CI: it needs an authenticated wp-env session and would roughly double job time. The navigation and layout specs for `basic-theme` are written from the theme's real markup and were first verified by CI (no local Docker).

### 4. Generated themes (`create-stratawp`)

- All templates depend on `@stratawp/stylelint-config` and the `@stratawp/testing` preset.
- Templates gain `lint:css` and `test:e2e` scripts and the config files that wire them up.
- Example themes and their `packages/cli/templates/*` twins are kept in sync by hand, as established in the earlier spec.
- Navigation smoke specs ship only in `examples/basic-theme`; templates get a generic layout spec.

### 5. CI and docs

- `ci.yml` runs stylelint; a new smoke workflow (or job) runs the browser matrix. Both are blocking.
- Docs updated, changeset added, decision logged in `.ai/PROJECT_RULES.md`.
- No reference to any external project in code, comments, docs, commits, or branch names.

## Testing

- **Images:** Vitest tests next to `images.test.ts` for AVIF generation, encode-failure fallback, and the formats opt-out.
- **Stylelint config:** per-rule fixture CSS that must pass and must fail, run through the config in a test.
- **PHP helper:** tests for source ordering and for the missing-sibling-file case.
- **E2E:** smoke tests run on all three browsers in CI.
- **Templates:** a scaffold test generates a theme from each template and runs `lint:css` on the output.

## Rollout order (one PR, ordered commits)

1. `@stratawp/stylelint-config` and the example-theme/template CSS fixes (riskiest, goes first).
2. AVIF in the vite-plugin and the PHP helper.
3. Smoke Playwright config, smoke tests, CI wiring.
4. Template updates and scaffold test.
5. Docs, changeset, `.ai/PROJECT_RULES.md` entry.

## Risks

- Size of the CSS cleanup is unknown until stylelint runs against the examples.
- WebKit/Firefox installs add CI time.
- A new published package needs an npm trusted-publisher entry before its first CI publish (see publish workflow notes).
- The earlier a11y spec requires `COMPOSER_MIRROR_PATH_REPOS=1` for wp-env boots; the smoke job reuses that boot sequence.
- An untracked stray plan file in `docs/superpowers/plans/` must never be staged.

## Out of scope

- AI tooling (theme-review skill, visual regression, theme-type awareness): sub-project 2.
- Design tokens, blocks/components, Site Editor sync, child-theme generator: later sub-projects.
