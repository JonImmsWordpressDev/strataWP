# Quality Gates

StrataWP ships three gates that apply to the monorepo and to every theme generated by `create-stratawp`: modern image formats (AVIF and WebP), a strict shared Stylelint preset, and a cross-browser smoke-test preset. The Stylelint and smoke gates are blocking in CI.

## AVIF and WebP

`@stratawp/vite-plugin` writes sibling files next to each optimized raster image: `hero.jpg` produces `hero.avif` and `hero.webp`.

```ts
stratawp({
  performance: {
    images: {
      formats: ['avif', 'webp'], // default
      quality: { avif: 50 }, // default
    },
  },
})
```

- `performance.images.formats`: which sibling formats to emit. Default `['avif', 'webp']`. Use `['webp']` to opt out of AVIF.
- `quality.avif` (under `performance.images`): AVIF encoder quality, default `50`.
- Legacy `webp: false` still removes WebP from the output.
- If encoding fails for a file, the build warns and skips that format for that file. The build does not fail.

Warnings:

- **AVIF is now emitted by default.** Build time and output size grow. Opt out with `formats: ['webp']`.
- **Already-built siblings are not regenerated when `quality` or `formats` change.** Freshness is judged only by the source file's modification time. Delete `dist/images` to force a rebuild. Dropping a format does not delete its old siblings.

### Rendering a `<picture>`

`StrataWP\Components\ImageSizes` provides two methods. Paths are relative to the theme directory (for example `dist/images/hero.jpg`).

- `get_picture_sources( string $relative_path ): array` returns AVIF then WebP sources, only for siblings that exist on disk.
- `render_picture( string $relative_path, string $alt, array $attributes = array() ): string` returns a `<picture>` element, or a bare `<img>` when no sibling files exist.

Both return an empty result for unsafe paths (traversal, absolute paths, NUL bytes) or a missing original. `render_picture()` drops attributes whose names are not lowercase `[a-z][a-z0-9-]*`, that start with `on`, or that are `src`, `srcset`, `alt` or `type`.

```php
$image_sizes = \StrataWP\Theme::instance()->component( 'image-sizes' );

if ( $image_sizes instanceof \StrataWP\Components\ImageSizes ) {
	echo $image_sizes->render_picture(
		'dist/images/hero.jpg',
		'A sunrise over the hills',
		array( 'class' => 'hero__image', 'loading' => 'lazy' )
	);
}
```

Output (AVIF and WebP `<source>` elements appear only when the files exist):

```html
<picture>
  <source
    type="image/avif"
    srcset="https://example.com/wp-content/themes/my-theme/dist/images/hero.avif"
  />
  <source
    type="image/webp"
    srcset="https://example.com/wp-content/themes/my-theme/dist/images/hero.webp"
  />
  <img
    src="https://example.com/wp-content/themes/my-theme/dist/images/hero.jpg"
    alt="A sunrise over the hills"
    class="hero__image"
    loading="lazy"
  />
</picture>
```

## Stylelint

`@stratawp/stylelint-config` is a shared preset. Generated themes already depend on it. To add it elsewhere:

```bash
pnpm add -D stylelint @stratawp/stylelint-config
```

`stylelint.config.js`:

```js
export { default } from '@stratawp/stylelint-config'
```

Run it with `pnpm lint:css`. `.scss` files are parsed with `postcss-scss`.

### Rules

| Rule                       | Default                      | Why                                                                        |
| -------------------------- | ---------------------------- | -------------------------------------------------------------------------- |
| `max-nesting-depth`        | `3`                          | Deep nesting compiles to long, brittle selectors.                          |
| `selector-max-specificity` | `0,3,1`                      | Low specificity keeps overrides cheap and the cascade predictable.         |
| `custom-property-pattern`  | kebab-case, `--` segments ok | Matches WordPress-generated tokens such as `--wp--preset--color--primary`. |

Depth semantics: depth 3 means three nesting levels inside the root rule. Four selectors deep passes, five fails. Pseudo-classes (`&:hover`) and at-rules (`@media`, `@supports`, `@container`, `@include`) do not count. Nested selectors are resolved before the specificity rule applies, so one deeply nested rule can trigger both rules.

WooCommerce exception: files matching `**/*woocommerce*.{css,scss}` use a higher specificity cap of `0,5,2`. Overrides of WooCommerce core selectors must match their specificity to win. The global cap stays `0,3,1`.

### Overriding a threshold

Override any rule in your own config:

```js
import preset from '@stratawp/stylelint-config'

export default {
  ...preset,
  rules: {
    ...preset.rules,
    'max-nesting-depth': [4],
  },
}
```

## Smoke tests

`@stratawp/testing/config` exports `createSmokeConfig`, `resolveBrowsers` and `checkSiteReachable`.

```ts
// playwright.smoke.config.ts
import { createSmokeConfig } from '@stratawp/testing/config'

export default createSmokeConfig({ testDir: './e2e/smoke' })
```

Options: `testDir` (required), `baseURL` (optional), `browsers` (optional).

Environment variables:

- `STRATAWP_E2E_BROWSERS`: comma-separated list of engines (for example `chromium,firefox`). Overrides the defaults.
- `WP_BASE_URL`: site under test. Default `http://localhost:8888`.

CI runs Chromium, Firefox and WebKit. Local runs default to Chromium. A global setup fails fast with one clear error if the site is unreachable.

Run the suite from the repo root with `pnpm test:smoke`, which targets `examples/basic-theme`. The axe accessibility gate (`pnpm test:e2e`) is unchanged and stays Chromium-only.

Every template ships `playwright.smoke.config.ts` and a generic `e2e/smoke/layout.spec.ts`. Navigation and layout specs for `examples/basic-theme` are written from that theme's real markup. Template e2e specs are not run in CI.

## CI

| Workflow          | Gate                                               | Blocking |
| ----------------- | -------------------------------------------------- | -------- |
| `ci.yml` (js job) | `pnpm lint:css`                                    | Yes      |
| `smoke.yml`       | Chromium, Firefox and WebKit smoke tests on wp-env | Yes      |
| `a11y.yml`        | axe-core, Chromium only (unchanged)                | Yes      |
